# 第二阶段与服务器运行说明

## 数据与质量策略

- arXiv 是必需主数据源；Hugging Face Daily Papers 是社区热度补充。
- `qwen3.7-max` 同时负责候选评分和 Top 3 PDF 正文证据审阅。
- GitHub 先识别摘要中的显式仓库；没有显式链接时才按标题搜索，匹配置信度不足不展示。
- 社区信号最多为基础评分增加 0.9 分，避免热度压过论文内容质量。
- PostgreSQL 保存每次运行、论文快照、评分、社区信号与正文证据；事件时间全部为 `TIMESTAMPTZ`。

## 隔离边界

- 安装目录：由私密部署配置中的 `INSTALL_ROOT` 指定。
- Agent：`127.0.0.1:8787`
- n8n：`127.0.0.1:5678`
- PostgreSQL：仅 Docker 内网，不发布主机端口
- Compose 项目名、容器名、网络和数据卷均为 `ai-research-agent` 专属资源。
- 总 CPU 硬上限 1 核，总内存硬上限约 1.6 GiB，且不允许占用 swap。
- 三个容器均使用低 CPU shares、较高 OOM 淘汰分，并限制进程数与日志大小。
- 每日任务在 04:30 JST 业务低峰运行。
- 日报成功生成后，通过飞书自建应用向配置的群聊或用户推送精简摘要；群聊与私聊分别按日期去重，失败最多重试 3 次并独立记账。

## 发布与回滚

每次发布解压到 `releases/<UTC timestamp>`，`current` 符号链接指向当前版本。发布脚本只有在 Compose 配置校验、镜像构建、两项 HTTP 健康检查、日报冒烟测试和数据库查询全部通过后才完成；失败时恢复 `current` 到上一版本并重新启动上一套定义。

运行密钥位于 `${INSTALL_ROOT}/shared/app.env`，权限强制为 `600`，不进入发布包或 Git。
